# Qaita — реабилитолог в каждой вебкамере

> **Черновик README** (ночь 28→29.09). Финальный `README.md` — файл Ерсултана: он берёт отсюда, что нужно.
> Всё про режим «ошибка» описано **по коду** `main` на 28.09 21:10 (коммит `19040ee`, все 5 упражнений и 8 ошибок). Если пороги поменяются после плейтеста, сверьте таблицу с `src/engine/mistakes.js`.

**Qaita** (каз. «қайта» — «снова») — домашний тренажёр для упражнений на руку после инсульта. Открываете ссылку, садитесь перед вебкамерой. Приложение считает повторы, **замечает компенсации** (наклон корпуса, плечо к уху, согнутый локоть) и голосом подсказывает, что исправить, как реабилитолог рядом.

🔗 **Демо:** https://marvindpp.github.io/qaita/
👥 Команда **«Хастлеры»** — ADMIT Hackathon «Motion» 2026, направление: здоровье / реабилитация.

> ⚕ **Не медицинское изделие.** Qaita не ставит диагноз и не заменяет врача. Это компаньон для упражнений, которые **уже назначил** врач или реабилитолог. Больно — остановитесь.
> 🔒 **Видео не записывается и никуда не отправляется.** Распознавание работает прямо в браузере (MediaPipe, WebAssembly/GPU). Из интернета загружаются только файлы моделей.

## Запуск

**Проще всего:** откройте https://marvindpp.github.io/qaita/ в Chrome / Edge / Safari и разрешите камеру.

**Локально** (нужен Node.js 20+):
```bash
npm i
npm run dev        # → http://localhost:5173  (камера работает на localhost)
```
| Адрес | Что это |
|---|---|
| `http://localhost:5173/` | приложение |
| `http://localhost:5173/?mock=1` | интерфейс без камеры: виртуальный пациент (mock-движок) |
| `http://localhost:5173/?debug=1&auto=1` | проверка движка без интерфейса: скелет и сценарий калибровка → 5 упражнений (`&ex=reach_up,open_hand` — выбрать, `&reps=3`; `?debug=2` — с цифрами метрик) |

```bash
npm test           # unit-тесты движка (vitest)
npm run build      # сборка в dist/
```
Деплой: каждый push в `main` → GitHub Actions (тесты + сборка) → GitHub Pages.

### Как сесть (экран «Подготовка» проверяет это сам)
1. Сядьте на стул, лучше без подлокотников.
2. Камера на уровне груди, примерно в 1 м.
3. Свет спереди, не спиной к окну.
4. В кадре голова, плечи, обе руки и место над головой.
5. Больно — стоп: две ладони к камере = пауза.

## Управление без мыши: жесты

| Жест | Команда | Как распознаём (`src/engine/gestures.js`) |
|---|---|---|
| ✋ **Ладонь 1 с** | ОК / дальше | 4 пальца выпрямлены (кончик дальше от запястья, чем средний сустав, в 1,15 раза). Удержание 1000 мс, кольцо заполняется по `progress` |
| 👍 **Палец вверх 0,7 с** | повторить подсказку голосом | большой палец вверх, остальные 4 согнуты |
| ✋✋ **Две ладони 0,8 с** | пауза («Больно? Отдохните») | две открытые ладони |
| 🙋 **Поднять руку 1 с** | выбрать руку для тренировки | запястье выше плеча на 0,3 ширины плеч, вторая рука опущена |

Жест срабатывает **один раз за удержание**, повтор — только после того, как руку опустили. Во время упражнения работают только «пауза» и «палец вверх»: там открытая ладонь — часть движения. На паузе жесты работают, иначе паузу не снять без мыши.

## Упражнения

Цель-звезда ставится на **105% личного максимума** из калибровки: у каждого своя, достижимая, но чуть дальше.
**Адаптивная сложность** (`session.js`): если человек чисто, без компенсаций, дотянулся дальше звезды, следующая звезда встаёт туда, где реально была рука. Каждые 3 чистых повтора подряд — ещё +5%. Общий потолок — **+40%** от калибровки: пожилым резкий рост сложности мешает.

| Упражнение | Движение | Статус |
|---|---|---|
| ★ **Звезда вверх** `reach_up` | подъём прямой руки вперёд-вверх (сгибание плеча) | звезда над плечом на 105% личного максимума, растёт |
| ★ **Звезда в сторону** `reach_side` | отведение руки в сторону (фронтальная плоскость, камера видит точнее всего) | звезда сбоку на 105% личного максимума, растёт |
| ☕ **Чашка ко рту** `hand_to_mouth` | функциональная задача «выпить чай» | цель — рот (чуть ниже носа по калибровке), не растёт |
| ↔ **Через себя** `reach_across` | ладонью к противоположному плечу | звезда за средней линией тела, растёт |
| 🖐 **Раскрыть ладонь** `open_hand` | кулак → ладонь (по 21 точке кисти) | повтор = все 4 пальца выпрямлены 0,5 с, потом снова кулак |

Повтор — это машина состояний `REST → REACHING → HOLD (0,5 с у звезды) → RETURNING → REST (+1)` (`src/engine/reps.js`). Повтор засчитывается, когда рука вернулась вниз. **Пока есть компенсация, удержание у звезды не идёт**: сначала исправься, потом звезда засчитается.

## Как реализован режим «ошибка»

Ошибка в Qaita — это не «не распознано», а **конкретная компенсация**. Так пациенты «обманывают» упражнение, и это закрепляет неправильный паттерн. Каждая подсказка отвечает на три вопроса: **что не так + что сделать + сколько** (см или градусы, если можно посчитать).

### 1. Личная норма вместо общей модели (`calibration.js`)
Калибровка «Твоя норма» проходит в 3 фазы, перед каждой отсчёт 3-2-1:
1. **Сидим ровно 3 с.** Берём **медиану** кадров: ширина плеч (S), центр плеч, плечо рабочей стороны, нос, расстояние ухо–плечо, ширина головы (ухо–ухо).
2. **Рука максимально вверх 3 с** → личный максимум вверх.
3. **Рука максимально в сторону 3 с** → личный максимум в сторону.

Таймер фазы идёт, **только когда человека (и руку) видно**. Первая фаза не начнётся, пока кадр плохой (свет, расстояние, локти не видны — `framing.js`). Все дальнейшие сравнения идут с **этой** нормой, а не с «идеальным человеком».

### 2. Детекторы компенсаций (`mistakes.js`)
Все расстояния меряются в **ширинах плеч S**: тогда неважно, далеко человек или близко. В сантиметры переводим через среднюю ширину плеч взрослого ≈ 37 см, поэтому в подсказке «~». Проверяем только **во время движения** (фазы `REACHING` и `HOLD`).

| Код | Как ловим (относительно нормы) | Порог | Подсказка (из кода) |
|---|---|---|---|
| `TRUNK_LEAN_FORWARD` | лицо (внешние уголки глаз) в кадре **выросло** — человек подался к камере. Если глаз не видно — ширина плеч. Или нос опустился | лицо > +12% (плечи > +15%) или нос ниже на 0,15·S | «Наклон вперёд на N см. Спину ровно!» |
| `TRUNK_LEAN_SIDE` | центр плеч или голова сместились вбок | центр плеч > 0,12·S или нос > 0,18·S | «Корпус вправо/влево на N см. Сядьте ровно!» |
| `SHOULDER_HIKE` | расстояние ухо–плечо рабочей стороны **сократилось** | короче на 20%; когда рука выше 90°, допуск до 35% (плечо естественно чуть поднимается) | «Плечо к уху на N см. Опустите плечо!» |
| `ELBOW_BENT` | угол плечо–локоть–запястье, когда рука уже вытянута (запястье дальше 1·S от плеча). Только `reach_up` и `reach_side`: в `reach_across` рука идёт к камере, и 2D-угол врёт | < 150° | «Локоть согнут. Выпрямите руку!» (угол — в `valueDeg`) |
| `TOO_FAST` | скорость запястья: быстро в **3 кадрах из 5** (одиночный скачок точки — не рывок). Подсказка держится 0,7 с | > 4,5·S в секунду | «Слишком быстро. Медленнее!» |
| `INCOMPLETE_ROM` | рука пошла к звезде (> 25% пути), но вернулась, не дойдя. Считаем, сколько не хватило до края круга. Подсказка висит 1,8 с и **не блокирует** следующий повтор | — | «Не хватило N см. Ещё чуть-чуть!» |
| `WRONG_HAND` | рабочая рука в покое, а другая поднята выше своего плеча | > 0,3·S | «Не та рука! Тренируем правую/левую» |
| `FINGERS_NOT_OPEN` | в `open_hand` раскрыто 2–3 пальца из 4 дольше 1,2 с. **Называем, какие пальцы согнуты** | 1,2 с | «Безымянный и мизинец согнуты. Раскройте ладонь!» |

Подсказки намеренно короткие, 3–5 слов: пожилой человек успевает прочитать и услышать их, не отвлекаясь от движения.

Почему наклон вперёд мерим **по лицу, а не по плечам:** на живом тесте 28.09 поднятая рука «растягивала» точки плеч в MediaPipe, и приложение ложно говорило «наклонились на 32 см». Лицо при подъёме руки не меняется. Сначала мерили по ушам, но поднятая рука закрывает ухо, поэтому теперь меряем по уголкам глаз. Это регрессионный тест в `tests/engine/reach_up.test.js`.

### 3. Надёжность: от «сырого» кадра к одной понятной подсказке
- **Сглаживание** точек: EMA, α = 0,5 (`smoothing.js`).
- **Видимость:** точки с `visibility < 0,5` не используем (`geometry.js`).
- **Debounce** (`tracker.js`): ошибка показывается, если держится **≥ 300 мс**, и снимается после **≥ 500 мс** без нарушения. Одиночный «глюк» кадра подсказку не вызывает (есть тест).
- **Приоритет: одна подсказка за раз.** Порядок: не та рука → корпус вперёд → корпус вбок → плечо → локоть → скорость → амплитуда → пальцы.
- **Проверяем с первого кадра движения**, а не только у звезды: в литературе у пациентов корпус начинает компенсировать **раньше** руки.
- **Звезда блокируется сразу**, по «сырому» сигналу, без ожидания 300 мс. Иначе быстрый повтор с компенсацией успел бы засчитаться. Не блокируют только `INCOMPLETE_ROM` и `WRONG_HAND`: они про прошлое движение или про другую руку.
- **Исправился → хвалим:** событие `mistake-cleared`, UI показывает «Отлично, так правильно!». Считаем `mistakesCorrected` для итогов.
- **Качество повтора** = 1 − доля кадров с нарушением.
- Повтор одной и той же подсказки голосом — не чаще раза в 4 с (это делает UI).

### 4. Статусы кадра (это не ошибки движения, но тоже с подсказкой, `framing.js`)
`LOW_LIGHT` (средняя яркость < 55 из 255) · `TOO_FAR` (плечи < 14% ширины кадра) · `TOO_CLOSE` (плечи > 42%, или над плечами меньше 1,2·S места для поднятой руки) · `LOW_VISIBILITY` (не видно локтей) · `NO_PERSON` (> 1 с без позы) · `NO_CAMERA`.

### 5. Тесты
Правила проверяются unit-тестами на **синтетических позах** (`tests/engine/synth.js`): «правильное движение → +1 повтор и **ноль** ошибок» (отрицательный контроль), каждая компенсация → нужный код, подсказка с числом, исправление → `mistake-cleared` → повтор засчитан. `npm test`.

## Архитектура

```
index.html, styles/         [UI]
src/main.js                 выбирает движок: настоящий или ?mock=1
src/contract.js             ← граница: константы событий, ошибок, жестов (docs/CONTRACT.md)
src/engine/                 [движок, без DOM, кроме своего <video>]
  camera.js   models.js     getUserMedia 640×480 · MediaPipe Pose (lite) + Hand, GPU → CPU
  loop.js     smoothing.js  requestVideoFrameCallback · EMA · зеркало (селфи-вид)
  body.js     geometry.js   снимок тела за кадр: плечи, локоть, запястье, углы, в «ширинах плеч»
  framing.js                проверка кадра (свет, расстояние, видимость)
  calibration.js            «Твоя норма»
  exercises.js  reps.js     цель-звезда · машина состояний повтора
  mistakes.js   tracker.js  детекторы компенсаций · debounce + приоритет
  session.js                одно упражнение: кадр → ошибки → повторы → события
  gestures.js               ладонь, палец вверх, пауза, поднять руку
  index.js                  createEngine(): собирает всё, шлёт события
src/mock/                   mock-движок с тем же API (UI делается без камеры)
src/ui/                     экраны, голос, звук, прогресс
tests/engine/               unit-тесты движка
```

**Движок и интерфейс общаются только событиями** (`frame`, `status`, `calibration`, `target`, `rep`, `mistake`, `mistake-cleared`, `gesture`, `exercise-done`) и методом `getSummary()`. Контракт — `docs/CONTRACT.md`. UI не считает углы, движок не трогает DOM. Тексты подсказок пишет движок, потому что знание о теле должно быть в одном месте.

**Стек:** Vanilla JS + Vite, `@mediapipe/tasks-vision` 1.0.1, Vitest. Без фреймворков и без бэкенда. Прогресс хранится в `localStorage`.
